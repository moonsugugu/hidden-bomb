# 💣 히든밤 (hidden-bomb)

**이종대왕X문수네집 콜라보 게임앱**

주사위를 굴려 나온 숫자만큼 **연속으로 정답 카드**를 골라야 하는 실시간 교실 게임입니다.
폭탄(오답) 카드를 밟으면 그 차례는 끝납니다.

담임 선생님이 모둠 방을 최대 **7개**까지 열고, 학생들이 **QR로 입장**해 모둠당 **2~4명**이 겨룹니다.

운영 주소: <https://hiddenbomb.moonsunezip.com>

## 게임 규칙

- 덱 40장 중 **30%가 폭탄(오답)**입니다. (설정에서 10~50% 조절)
- 3×3 격자에 9장을 뒷면으로 깔고 나머지는 더미로 둡니다.
- 자기 차례에 주사위를 굴려 나온 숫자 N만큼 카드를 연속으로 통과하면 **N점**을 얻습니다.
- 중간에 폭탄이 터지면 그 차례는 0점으로 끝나고 다음 사람에게 넘어갑니다.
- 쓴 카드는 더미에서 바로 새 카드로 채웁니다. 더미가 다 떨어지면 게임이 끝납니다.
- 한 판은 대략 10~15분입니다.

### 자동 판정 (기본 6초)

카드를 열면 문장이 방 안의 친구 모두에게 동시에 보입니다. 모둠이 함께 정답을 예상할
시간을 가진 뒤, 설정한 시간이 지나면 서버가 카드의 실제 참·거짓을 자동으로 공개합니다.
사람이 **⭕ 맞아요 / 💣 폭탄이에요**를 누르지 않아도 되며, 선생님 화면에서 **3~15초를
1초 단위로 조절**할 수 있습니다.

### 주사위

성공 확률은 `0.7^N` 이라 5~6이 나오면 12~17%로 뚝 떨어집니다.
좌절하는 차례가 너무 많아지지 않도록 **기본값은 1~4면**입니다. 설정에서 1~3 또는 1~6으로 바꿀 수 있습니다.

| 주사위 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- |
| 성공 확률 | 70% | 49% | 34% | 24% | 17% | 12% |
| 기대 점수 | 0.70 | 0.98 | **1.03** | 0.96 | 0.84 | 0.71 |

## 문제 유형 4가지

### 🔢 연산 (자동 생성 · 준비 시간 0분)

학년별로 고를 수 있고, 문제는 교육과정에 맞는 학년군에서 무한히 만들어 냅니다.

| 학년군 | 덧셈·뺄셈 | 곱셈 | 나눗셈 |
| --- | --- | --- | --- |
| 1~2학년 | 두 자리(받아올림·받아내림) | 구구단 | — |
| 3~4학년 | 세 자리 | 두 자리 × 한 자리 | 나머지 있는 나눗셈 |
| 5~6학년 | 분수·소수 | 두 자리 × 두 자리, 소수 | 세 자리 ÷ 두 자리 |

**폭탄 카드는 무작위 숫자가 아니라 학생이 실제로 자주 하는 실수로 만듭니다.**
무작위 오답은 티가 나서 판별 게임이 성립하지 않습니다.

| 오류 유형 | 폭탄 카드 | 바른 답 |
| --- | --- | --- |
| 받아올림 누락 | `27 + 15 = 32` | 42 |
| 받아내림 대신 큰 수−작은 수 | `52 - 27 = 35` | 25 |
| 구구단 한 칸 밀림 | `3 × 8 = 27` | 24 |
| 부분곱 자리 안 밀기 | `23 × 14 = 115` | 322 |
| 분자·분모끼리 계산 | `1/2 + 1/3 = 2/5` | 5/6 |
| 소수점 위치 | `0.3 × 0.4 = 1.2` | 0.12 |
| 나머지 무시 | `17 ÷ 5 = 3` | 3···2 |

터지는 순간이 학생 집중도가 가장 높은 때라, 그때 바른 답과 이유를 함께 보여 줍니다.

### ✏️ 맞춤법

1~2학년(받침·소리와 표기), 3~4학년(되/돼, 안/않, 왠/웬), 5~6학년(로서/로써, 부치다/붙이다 등).

### 📋 명제

**과목**(수학·과학·사회·국어·영어) × **학년군**(1~2 / 3~4 / 5~6) = 15개 세트.
맞춤법 3세트까지 합쳐 **내장 문항 4,480개**(기본 문항의 10배)이고, 모든 조합이 4×4 격자(19장)까지 감당합니다.
선생님 화면에서 **1·2·3·4·5·6학년**과 과목을 세트별로 골라 바로 적용할 수 있습니다. 인접 학년은 같은 학년군 문제은행을 사용해요.

> 1~2학년은 과학·사회 교과가 없어 통합교과(봄·여름·가을·겨울) 수준의 문장으로 구성했습니다.

명제는 참·거짓이 문장에 고정되어 있어 한쪽이 모자라면 폭탄 비율이 틀어집니다.
그래서 **비율을 먼저 지키고 덱 크기를 줄입니다.** 짧은 게임이 불공정한 게임보다 낫기 때문입니다.
어떤 설정이 문제가 모자라면 선생님 화면에서 **시작 전에** 경고하고 시작 버튼을 잠급니다.

### 📊 직접 올리기 (엑셀)

`문장 / 정답(O·X) / 해설` 세 칸짜리 양식을 내려받아 채운 뒤 `.xlsx`, `.csv`, `.tsv`로 올립니다.
**파일은 서버로 전송되지 않고 브라우저에서만 읽습니다.**

## 선생님 화면

- 모둠 방 최대 7개, 방마다 **입장 QR + 4~5자리 코드**
- **QR 크게 보기 · 인쇄** — 모둠 수만큼 잘라서 책상에 두면 됩니다
- 모든 모둠의 인원·점수·차례·진행 상황 실시간 표시
- 설정할 방을 고른 뒤 **모둠별 설정 적용** / 전체 설정 적용
- 전체 시작 / 모둠별 시작·턴 넘기기·끝내기
- **💣 많이 터진 문제** 히트맵 — 수업 마무리 자료로 바로 쓰고 CSV로 내려받을 수 있습니다

## 참여 방식 두 가지

### 한 사람이 한 기기
학생마다 자기 기기로 QR을 찍고 들어옵니다. 7모둠이면 최대 28대가 필요합니다.

### 한 기기를 같이 쓰기 (모둠 1기기 모드)
태블릿이 **모둠당 한 대**뿐인 교실을 위한 모드입니다.
입장할 때 모둠원 2~4명의 이름을 한 번에 적으면 그 기기가 모둠 전체를 맡습니다.
차례가 되면 화면에 **"🔄 ○○에게 기기를 넘겨 주세요"**가 뜨고, 기기를 넘겨받은 사람이 조작합니다.
원래 보드게임에 오히려 더 가깝고, **태블릿 7대만 있으면 한 학급이 다 돌아갑니다.**

두 방식은 한 방에서 섞어 써도 됩니다. 기기가 있는 학생은 따로, 없는 모둠은 같이 쓰면 됩니다.

## 교실에서 쓸 때

- 학생 기기가 모둠당 1~4대 필요합니다. (1기기 모드면 모둠당 1대)
- 카드 문장은 태블릿에서 최소 28px로 보이도록 `clamp()`로 잡았습니다.
- 태블릿 가로모드에서는 왼쪽에 문제판, 오른쪽에 현재 문제와 주사위가 나옵니다.
- 친구가 살펴보는 카드는 모든 화면에서 👀 표시와 테두리로 함께 강조됩니다.
- 터치 타겟은 최소 60px, 안전/폭탄은 색이 아니라 **💣 ✅ 아이콘**으로도 구분합니다.
- 폭탄·정답 공개에는 아이콘 파티클과 부드러운 강조 효과를 넣되 **번쩍임은 쓰지 않습니다.** (광과민성 고려, `prefers-reduced-motion` 존중)
- 학생은 **닉네임만** 입력합니다. 계정·이메일을 받지 않습니다.
- 와이파이가 끊기거나 태블릿이 절전에서 깨어나면 자동으로 다시 붙습니다.
- 차례인 학생이 60초 동안 반응이 없으면 자동으로 넘어가고, 접속이 끊기면 15초 만에 넘어갑니다.

## 로컬 실행

```powershell
npm install
npm run server   # 게임 서버 (127.0.0.1:3203)
npm run dev      # 웹 (127.0.0.1:3005)
```

브라우저에서 <http://127.0.0.1:3005> 를 엽니다.

> 같은 브라우저에서 학생 두 명을 흉내 내려면 탭마다 `localStorage`의 `hidden-bomb-*` 키를
> 지워야 합니다. 같은 기기로 붙으면 같은 참가자로 재접속되기 때문입니다.
> (실제 교실에서 한 기기로 여러 명이 참여할 때는 위의 **모둠 1기기 모드**를 쓰면 됩니다.)

## 테스트

```powershell
npm run test:server
```

95개 테스트가 있습니다.

- `generators.test.mjs` — 생성기와 **독립적으로 식을 다시 계산**해서 `isTrue` 표시가 맞는지 검증합니다.
  폭탄 카드가 실수로 맞는 식이면 게임이 성립하지 않고, 정답 카드가 틀린 식이면 아이들에게 틀린 수학을
  가르치게 되므로 가장 중요한 검증입니다. 한 번 돌 때마다 약 4,800장을 검산합니다.
- `question-bank.test.mjs` — 정답 문장과 폭탄 문장이 같지 않은지, 모든 과목·학년군에 문제가 있는지 확인합니다.
- `bomb-game.test.mjs` — 규칙, 점수, 턴 진행, 접속 끊김 처리, **뒷면 카드 내용이 새어 나가지 않는지** 확인합니다.
- `e2e.test.mjs` — 실제 WebSocket 서버를 띄워 선생님 → 학생 흐름 전체를 확인합니다.

## 정답 유출 방지

전체 덱을 클라이언트에 내려보내면 개발자 도구로 정답을 미리 볼 수 있습니다.
그래서 **뒷면 카드는 내용 없이** 자리 정보만 보내고, 카드를 여는 순간에만 문장을 보냅니다.
자동 판정 대기 중에는 학생이 고르기 전까지와 마찬가지로 정답 여부(`isTrue`)와 해설을 보내지
않습니다. 설정 시간이 지난 뒤에만 카드의 정답과 해설을 공개합니다.

아무도 없는 방은 60초 뒤 자동으로 정리됩니다.

| 서버는 `HOST`, `PORT` 환경변수를 읽고 기본값을 `127.0.0.1` 로 | 주소를 `0.0.0.0` 으로 코드에 고정하면 서버 설정으로 바꿀 수 없음 |
| **IP 당 제한을 걸지 마세요** | 학교는 전교생이 **공인 IP 하나**로 나갑니다. 윷놀이의 "IP당 방 6개" 제한이 학교 전체를 막았습니다 |
| 방 상태 전송 시각·타이머는 **방마다 따로** | 전역 변수 하나로 두면 한 반의 활동이 다른 반 갱신을 밀어냅니다(줄다리기에서 최장 4초 멈춤) |
| 큰 상태를 자주 보내면 WebSocket 압축(`perMessageDeflate`) | 줄다리기 20개 반 기준 161Mbps → 3Mbps |
| 끊긴 학생이 **60초 안에 같은 자리로 재접속**할 수 있게 | 교실 와이파이는 자주 끊깁니다. 빈 방도 60초는 유지하세요 |
| 요청 처리 중 동기 파일 I/O·느린 OS 호출 금지 | Windows 에서 `os.networkInterfaces()` 1회 25ms → 30명 방에서 서버가 멈췄습니다 |
| 요청마다 목록 전체를 훑는 코드 금지 | 사용자가 늘수록 느려집니다(backend 처리량이 4분의 1이던 원인) |
| 비밀값(키·비밀번호)은 저장소에 넣지 않기 | 서버의 비밀값은 `C:\homeserver\secrets` 에 따로 있습니다 |

**부하 목표: 한 학교 20개 반 동시 사용(약 600명).** 전국 배포라 한글날처럼 특정 날에 몰립니다.

## 📏 코드 규칙 (coderule)

> 이 저장소를 고치기 전에 **[moonsugugu/coderule](https://github.com/moonsugugu/coderule)** 을 먼저 읽으세요. 사람과 AI 모두 지킵니다.

**핵심 다섯 가지**

1. **30명 반 하나의 전송량은 1Mbps 이하.** `메시지 크기(바이트) × 초당 횟수 × 받는 사람 수 × 8 ÷ 1,000,000` 으로 완료 전에 잰다.
   2026-10-02 고조선이 30명 방 하나에 22Mbps를 써서, 20개 반이 몰리자 집 업로드(약 170Mbps)가 막혀 모든 앱이 끊겼다.
2. **바뀐 것만 보내고, WebSocket 압축(`perMessageDeflate`)을 켜고,** 위치처럼 계속 바뀌는 값은 초당 5~7회 + 화면 보간. 입력마다 즉시 방송하지 말고 50~150ms 모아서 보낸다.
3. **인원 제한에 선생님을 세지 않는다. IP당 제한을 걸지 않는다**(학교는 전교생이 공인 IP 하나).
4. **방마다 타이머 따로, 끊긴 학생은 60초 이상 같은 자리 유지,** 서버는 `HOST`·`PORT` 환경변수(기본 `127.0.0.1`), 요청 경로에 동기 I/O 금지.
5. **배포·앱 재시작·터널 재시작은 서버 관리자에게 물어보고 한다.** 배포 = 서버 재시작 = 진행 중인 방이 전부 사라진다. (README 같은 `.md` 문서만 바꾼 push는 재시작 없이 반영된다)

**이 저장소 점검(2026-10-02):** 4인 모둠 턴제라 일이 생길 때만 보내 전송량 문제는 적었습니다. WebSocket 압축과 HOST 환경변수를 적용했습니다.

## 재접속·QR·부하 점검 (2026-10-02)

- 선생님/방장 화면에서 참가 QR을 클릭하면 팝업이 열립니다. 180~720px 슬라이더와 확대·축소 버튼, Esc·바깥 클릭 닫기를 지원하며 작은 화면에는 QR 전체가 보이도록 맞춥니다.
- 같은 기기·브라우저의 새로고침/다시 입장에서 기존 참가 정보와 방별 자리를 복원합니다. 실제 계정 로그인 기능이 없는 게임은 참가 자리 복귀를 뜻합니다.
- 방별 80ms 방송 묶음, 변경된 필드만 전송, WebSocket 압축, 입력 빈도 제한과 256KiB 전송 대기열 제한을 적용합니다. 새 화면은 delta=1로 협상하고 기존 화면은 전체 상태를 받아 배포 전후 호환을 유지합니다.
- 기존 참가자의 경기 중 재접속은 허용합니다. 새 기기에서는 접속이 끊긴 원래 이름으로 자리를 복원합니다. 경기 중 처음 들어오는 신규 참가자는 역할/턴 규칙 때문에 받지 않습니다.
- 학생이 남아 있으면 교사 연결이 끊겨도 통합방을 삭제하지 않습니다. 모든 참가자가 떠난 뒤 최소 60초 보관합니다.
